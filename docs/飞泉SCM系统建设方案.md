# 飞泉SCM系统建设方案

## 1. 项目概述

### 1.1 项目背景

飞泉智能装备（苏州）有限公司的采购与供应链管理目前分散在 Excel 台账、邮件审批与纸质单据之间：供应商资质靠人工登记与提醒，请购—询价—下单—收货—对账链条缺乏系统化的闸口控制，库存补货依赖计划员个人经验，财务三单匹配（订单 / 收货 / 发票）在对账时才发现差异。本项目建设「飞泉SCM系统」，把**供应商管理、采购执行、仓储库存、结算付款**四条主线收敛到一个系统内，并预留标准化开放接口，供后续与 ERP / WMS / 财务系统对接。

### 1.2 建设目标

- **全流程线上化**：请购 → 询价比价 → 采购订单 → 收货质检 → 入库 → 发票 → 付款 → 结算，全链路单据化、状态机化、留痕化。
- **闸口式风控**：每个关键动作都有明确的准入闸口（审批人、供应商准入、到货数量、三单匹配），不满足则系统拒绝，杜绝「先斩后奏」。
- **库存透明**：批次级库存台账，安全库存 / 补货点 / 覆盖天数 / 库龄 / 效期自动计算，缺料与近效期主动预警。
- **供应商可评价**：四维绩效（交付 35 / 质量 35 / 价格 15 / 协同 15）自动算分定级，与准入 / 限单 / 冻结联动。
- **开放集成**：API Key + Webhook + 增量同步三条通道，82 条 REST 路由全部对外可用。
- **零依赖可交付**：仅用 Python 标准库实现，单机可跑、离线可用，交付即演示。

### 1.3 建设范围

| 模块 | 内容 |
|---|---|
| 主数据 | 供应商档案（360 视图 + 资质 + 绩效）、物料主数据（价格 / 仓存 / ABC）、仓库 |
| 采购执行 | 请购单、询价比价、采购订单（状态机 + 闸口）、收货质检 |
| 库存 | 批次库存台账、出入库流水、仓间调拨、库存盘点、库存调整 |
| 结算 | 发票登记、三单匹配、付款、应付账龄 |
| 分析 | 供应链驾驶舱、报表分析（9 模块） |
| 集成 | API Key、Webhook、投递记录、外部 ID 映射、增量变更流 |
| 系统 | 业务规则、用户与角色、操作日志 |

## 2. 总体架构

### 2.1 技术选型（零依赖原则）

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | Python 标准库 http.server | 单进程多线程 HTTP 服务，无框架 |
| 存储 | SQLite（WAL 模式） | 单文件库，`busy_timeout=20000`，全局 RLock 串行化 /api/ 请求 |
| 业务内核 | backend/scm.py 纯函数 | 无 IO / 无 SQL，所有业务口径集中在此，100% 可单元测试 |
| 前端 | 原生 HTML/CSS/JS | hash 路由 + F 命名空间，零构建零依赖 |
| DEMO | 单文件 HTML | 数据快照内嵌 + fetch 拦截器，离线双击可用 |

### 2.2 系统分层

```
┌─────────────────────────────────────────────┐
│  前端 14 页（app/mdm/buy/stock/fin/intg.js）  │
├─────────────────────────────────────────────┤
│  HTTP 层：82 条路由 · 多通道取票 · 限流 · 幂等  │
├─────────────────────────────────────────────┤
│  业务层：视图函数 + 写操作（权限/校验/事件）     │
├─────────────────────────────────────────────┤
│  业务内核 scm.py：评级/状态机/三单/库存/账期    │
├─────────────────────────────────────────────┤
│  数据层 db.py：34 表 + 8 索引（SQLite WAL）    │
└─────────────────────────────────────────────┘
        ↘ 集成三通道：REST / Webhook / 增量同步
```

### 2.3 关键工程约定

- **金额一律 `r2`（分位）**、比率 `r4`（4 位），杜绝浮点噪声穿透到界面与报表。
- **所有写操作**经 `@write_op`：统一权限校验 → 业务校验 → 落库 → 操作日志 → 事件 emit → 变更流。
- **幂等**：写接口支持 `Idempotency-Key` 头，重复请求返回缓存响应。
- **限流**：API Key 调用按分钟窗口限 240 次，超限返回 429 + Retry-After。

## 3. 业务域设计

### 3.1 供应商管理

- **档案**：编码 `SUP-0001`，含类别 / 联系人 / 账期 / 交期 / 主供物料；新建即查重（NFKC 归一 + 城市前缀与公司后缀剥离 + LCS 相似度 ≥0.62 判同名）。
- **资质**：证照名称 / 编号 / 有效期，状态自动判定（有效 / 临期（默认 30 天预警）/ 过期 / 未知）；**准入闸口：至少 1 项有效资质**；资质过期自动冻结。
- **绩效**：按季度录入交付及时率 / 质量合格率 / 价格指数 / 协同响应率，综合分 = 35d + 35q + 15p + 15r（价格分 = |指数−1| 每偏 1% 扣 1 分，扣完为止）。
- **等级**：A ≥85 / B ≥70 / C ≥55 / D <55。
- **健康状态**：资质过期 → 冻结；分数 <55 或逾期发票 ≥3 → 观察；逾期发票 >0 → 限单；否则正常。**已下单闸口要求供应商「已准入」**。

### 3.2 请购与询价

- **请购单**（PR）：部门 / 用途 / 需求日期 + 多行明细。状态机：草稿 → 待审批 → 已审批 → 已转单（另有已驳回 / 已取消）。
- **免审批金额**：金额 ≤5000 元时提交即自动通过（规则 `req_free_limit`）。
- **批准校验部门季度预算**，执行率超 100% 给出拦截提示。
- **询价单**（RFQ）：可由已审批请购发起，**至少 2 家供应商报价**（规则 `rfq_min_suppliers`）；报价登记支持同供应商覆盖更新；定标自动按标准价占比把总价分摊到明细并生成采购订单。

### 3.3 采购订单（状态机与闸口）

状态机：`草稿 → 待审批 → 已下单 → 部分到货 → 全部到货 → 已结算`，另有 `已取消`；**只能前进（可跨级）、不能回退、终态锁定**。

| 目标状态 | 闸口（po_gate） |
|---|---|
| 待审批 | 至少一行明细、金额 >0 |
| 已下单 | 有审批人、供应商「已准入」 |
| 部分到货 / 全部到货 | 有收货记录；全部到货要求到货量 ≥ 订购量 |
| 已结算 | 已登记发票且三单匹配「通过」（由财务推进） |

订单金额 >`po_approve_limit`（5 万）需采购总监审批。收货过账后按累计到货量自动推进「部分到货 / 全部到货」。

### 3.4 收货质检

- 收货单（GR）逐行登记合格 / 不良与批次效期；**质检结论：不良率 =0 → 合格；≤容差（2%）→ 让步接收；否则退货**。
- **只有合格品入库**；不良留单据退货。入库过账写「采购入库」流水，价格回写物料最近价与价格记录。

### 3.5 库存

- **批次台账**：物料 × 仓库 × 批次；现存量 / 占用 / 可用 / 单位成本 / 入库日 / 库龄 / 效期。
- **补货点** = 日均耗用 × 提前期 + 安全库存（向上取整）；**状态**：缺货 / 低于安全库存 / 待补货 / 正常 / 超储；**覆盖天数** = 现存量 ÷ 日均耗用。
- **缺料建议**：建议补货量补到最大库存（无则补到安全库存），含建议下单日（提前期 −3 天）与预计金额，支持**一键生成请购草稿**。
- **ABC 分类**：按「标准价 × 日均耗用 × 365」年耗用金额降序累计，判定用「加入本物料之前」的累计占比，A ≤70% / B ≤90% / 其余 C。
- **作业**：调拨（草稿→已审批→已完成，写调出 / 调入两条流水，执行时逐行校验调出仓库存，任一不足整单失败）、盘点（按仓库快照 → 录实盘 → 差异过账写盘盈 / 盘亏）、手工调整（盘盈 / 盘亏 / 领用出库 / 其他入库）。
- **效期**：近效期预警默认 90 天（规则 `expiry_warn_days`）。

### 3.6 结算付款（三单匹配）

- **匹配口径**：|发票额 − 收货额| ÷ 收货额 ≤ 容差（`match_tolerance` 默认 2%）→ 通过；无收货 / 无发票分别返回「无收货」「无发票」。
- 发票登记即匹配：通过 → 待付款；超限 → 差异挂起。**匹配未通过禁止付款**（硬闸口）。
- 付款支持部分付款，付满置「已付款」；订单结算由财务在三单匹配通过后推进。
- **应付账龄**：0-30 / 31-60 / 61-90 / 91-180 / 180 天以上五档。

## 4. 业务规则引擎

8 条可启停、可调阈值的规则（管理员操作，写操作日志）：

| 编码 | 名称 | 默认值 | 作用 |
|---|---|---|---|
| match_tolerance | 三单匹配容差 | 0.02 | 发票与收货金额差异率上限 |
| req_free_limit | 请购免审批金额 | 5000 | 低于此金额提交即自动通过 |
| po_approve_limit | 订单审批限额 | 50000 | 超限需采购总监审批 |
| qual_warn_days | 资质到期预警 | 30 天 | 驾驶舱资质预警清单 |
| expiry_warn_days | 效期预警天数 | 90 天 | 近效期批次判定 |
| rfq_min_suppliers | 询价最少家数 | 2 家 | 发起询价与定标的闸口 |
| price_deviation_warn | 价格偏离预警 | 0.05 | 成交价偏离标准价 5% 提示 |
| stock_cover_days | 库存覆盖天数 | 15 天 | 补货建议的目标覆盖参考 |

## 5. 角色与权限

五种权限位：`read`（全域读）/ `write`（建单改单）/ `approve`（审批定价）/ `stock`（库存作业）/ `finance`（结算付款）。

| 角色 | 权限 | 典型操作 |
|---|---|---|
| admin 系统管理员 | 全部 | 全域管理、集成中心、规则启停 |
| purchase_director 采购总监 | read/write/approve/finance | 审批请购订单、定标、结算确认 |
| buyer 采购专员 | read/write | 请购、询价、订单、收货（仅见自己名下单据） |
| planner 计划员 | read/write | 请购、缺料转请购 |
| warehouse 仓库主管 | read/stock | 调拨、盘点、库存调整、入库过账 |
| quality 质检员 | read/stock | 质检判定 |
| finance 财务专员 | read/finance/approve | 发票、三单匹配、付款、结算推进 |

数据范围：buyer 角色仅可见自己名下的采购单据；集成中心仅 admin 可见。

## 6. 数据模型

34 张表 + 8 个索引（SQLite），按域分组：

- **组织与系统**（6）：users / sessions / teams / rules / op_logs / budgets
- **供应商**（3）：suppliers / supplier_quals / supplier_scores
- **物料与仓库**（3）：materials / material_prices / warehouses
- **采购执行**（9）：requisitions / req_items / rfqs / rfq_items / rfq_quotes / purchase_orders / po_items / receipts / receipt_items
- **库存**（7）：stock / stock_moves / transfers / transfer_items / stocktakes / stocktake_items
- **结算**（1）：invoices
- **集成**（5）：change_log / api_keys / webhooks / webhook_deliveries / ext_mappings / idem_keys

关键索引：请购状态、订单供应商、收货订单、发票订单、库存物料、流水物料、变更对象、投递状态。

## 7. API 与集成设计

### 7.1 REST 概览

82 条路由（GET 37 / POST 39 / PUT 4 / DELETE 2），OpenAPI 3.0 规范 58 个路径，运行期可从 `/api/openapi.json` 获取。统一响应包 `{"ok": true, "data": …}` / `{"error": "…"}`。

### 7.2 鉴权

- **会话 Token**：登录签发，任意多通道传递（X-Fq-Token / X-Auth-Token / Authorization / Cookie / query / body，逐个校验取首个有效——反向代理改写头部也不掉登录）。
- **API Key**：前缀 `fqk_`，服务端仅存 SHA-256；请求头 `X-Fq-Key` 或 `Authorization: Bearer fqk_…`；scope 分 read / write，read 不能调用写接口；按分钟限流 240 次。

### 7.3 Webhook

- 事件 23 种（supplier.* / req.* / rfq.* / po.* / receipt.* / stock.* / invoice.*）。
- 头：`X-FQC-Event / X-FQC-Timestamp / X-FQC-Signature / X-FQC-Delivery`。
- 签名：HMAC-SHA256(secret, `timestamp + "." + body`)；接收方校验时间戳偏移 ≤5 分钟防重放。
- 重试：失败按 30 × 2ⁿ 秒退避，最多 3 次；最终失败保留投递记录，可手动重投。

### 7.4 增量同步

`GET /api/sync/changes?since={cursor}&object={obj_type}&limit=200`，返回 changes + cursor + hasMore；对接方首次 since=0 拉全量，之后按 cursor 续拉，与外部 ID 映射（`/api/integration/mappings`、`/api/integration/resolve`）配合实现双向主键对齐。

## 9. 指标口径

- **到货准时率** = 收货日期 ≤ 承诺日期的收货单数 ÷ 已收货收货单数（未到货不计分母）。
- **库存周转次数** = 期间出库成本 ÷ 期末库存金额；周转天数按 90 天折算。
- **价格指数** = 最新成交价 ÷ 标准价；节约率 =（标准价 − 成交价）÷ 标准价。
- **质检合格率** = 合格数 ÷（合格 + 不良）；**让步接收容差** 2%。
- **应付账龄** = 到期日之后自然日数，逾期 >0 标红。

## 10. 非功能设计

- **可移植**：纯标准库，Python 3.8+ 任意平台直接运行；数据单文件，随迁随用。
- **确定性数据**：种子数据固定随机种子（20261020），任何机器重建结果一致，便于培训与截图。
- **审计**：全部写操作进操作日志；业务变更进 change_log 供增量同步。
- **安全**：口令 SHA-256 加盐存储；API Key 仅存哈希；限流与幂等内建。
- **演示友好**：异常样本可控（缺货物料、近效期批次、临期资质、差异超限发票），驾驶舱预警区不空场。
