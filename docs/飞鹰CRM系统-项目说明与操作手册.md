# 飞鹰CRM系统 · 项目说明与操作手册

## 一、系统概览

飞鹰CRM 是「客户与销售全流程」管理系统，覆盖营销获客、客户经营、销售过程、交易与回款、客户服务、分析、系统设置七大板块，共 14 个功能页面、80 个 REST 接口。

交付形态：

| 形态 | 启动方式 | 用途 |
|---|---|---|
| 云端实例 | 直接打开 <https://drone-store.app.workbuddy.host/> | 免安装体验，演示数据已预置 |
| 正式系统 | `cd backend && python server.py`，浏览器打开 `http://127.0.0.1:8018` | 真实使用，数据落 SQLite |
| 离线 DEMO | 双击 `demo/飞鹰CRM系统Demo.html` | 演示与培训，无需服务与网络，写操作只在浏览器内存生效 |

## 二、启动与登录

### 1. 启动服务

```bash
cd backend
python server.py            # 默认端口 8018，首次启动自动建库并灌入演示数据

# 可选：换端口 / 换库文件
FEIYING_PORT=8020 FEIYING_DB=../data/crm.db python server.py
```

启动后访问 `http://127.0.0.1:8018`，未登录会自动跳到登录页。

### 3. 界面骨架

- 左侧「功能导航」按七大分组排列 14 个页面；
- 中间工作区：列表页统一「关键字 + 状态下拉 + chips 计数 + 新建按钮」，点击表格行打开详情弹层；
- 右侧「侧栏」放当前页的口径说明与结构统计；
- 底部状态栏：左侧显示操作结果（6 秒内不被页面摘要覆盖），右侧显示操作员、在谈商机、本月签约、期间。

## 三、销售驾驶舱（dashboard）

进入系统首页，六张 KPI 卡：在谈商机（加权）、本月签约、赢单率、逾期应收、待处理工单、客户/线索数。下方依次是销售漏斗（按金额，右侧带相邻阶段转化率）、近 6 个月签约趋势、待办与预警清单、我的在谈商机；侧栏是本月快照、签约 TOP 客户、待领取线索与当前生效的业务规则。

操作建议：每天先看「待办与预警」——逾期应收、超时工单、延期商机都在这里，点条目可直接跳转对应页面。

## 四、线索池（leads）

### 新建线索

1. 点「+ 新建线索」，填写公司名称、联系人、手机号（或邮箱）、来源、行业、区域、预算；
2. 手机号或公司名失焦时会自动查重，弹层内会提示「未发现重复 / 疑似重复：xxx（手机号相同）」；
3. 保存后按预算与来源自动分级：预算 ≥50 万 A、≥15 万 B，其余 C；来源「展会 / 老客推荐」上浮一档；
4. 保存时若命中重复，后端返回 409 并列出候选，确认要建可加 `force=true`（页面已默认允许强制保存，仅提示风险）。

### 线索流转

| 动作 | 入口 | 结果 |
|---|---|---|
| 分配 | 详情底部「分配」 | 指定负责人，状态转「跟进中」 |
| 领取 | 详情底部「领取线索」 | 公海线索归自己 |
| 写跟进 | 详情底部「写跟进」 | 生成跟进记录，刷新闲置天数 |
| 转客户 | 详情底部「转客户」 | 生成客户编码并跳转客户 360 |
| 标记无效 | 详情底部「标记无效」 | 必须填原因 |
| 回收公海 | 详情底部「回收公海」 | 释放回公海池 |

规则：超过 `pool_days`（默认 30 天）未跟进的线索会在回收任务中自动进入公海；公海线索任何销售可领取。

## 五、客户档案与客户 360（customers）

1. 列表展示编码、等级、健康分（含等级标签）、在谈商机、合同额、回款、未结工单、状态、负责人；
2. 顶部可按名称/编码/电话关键字、等级、状态过滤，支持导出 CSV（带 Token 下载）；
3. 点行打开「客户 360」弹层：六项统计 + 六个标签页（联系人 / 商机 / 报价 / 合同 / 工单 / 时间线）；
4. 弹层底部可直接「写跟进」或「建商机」（自动带入客户）。

健康分口径：跟进新鲜度 30 + 累计回款 40（对数缩放、30 万封顶）+ 在谈商机 20（3 个封顶）+ 满意度 10（5 分制），逾期回款每笔扣 8 分（最多 −24）。≥80 优质、≥60 健康、≥40 待经营，其余流失风险。

## 六、商机看板（opportunities）

- 默认看板视图，按六个阶段分列，卡片显示金额、赢率、加权、负责人与预计结单；可切「列表」视图做全字段浏览；
- 顶部漏斗条展示各阶段金额与数量；侧栏展示漏斗明细与结单情况（赢单/输单/平均客单）；
- 点卡片或行打开详情：金额、赢率、预计结单、距结单天数、竞品、决策人、**阶段闸口**（每个目标阶段缺什么一目了然）、**推进阶段**按钮组、阶段轨迹与最近跟进。

推进规则：

1. 只能前进，可跨级；不能回退；
2. 进入「需求确认」须有决策人；「方案报价」须有金额；「商务谈判」须决策人 + 竞品；「赢单」须已签署合同；
3. 推进「商务谈判」时页面会追问竞品与决策人，填完即校验并落库；
4. 「标记输单」必须填原因；赢单只能从「商务谈判」进入；
5. 结单后锁定，需重新立项。

## 七、跟进记录（activities）

- 顶部 chips 按方式过滤（电话/拜访/邮件/会议/微信）；列表展示时间、对象、方式、主题、内容、下一步计划；
- 各详情弹层里的「写跟进」都会写到这里，口径一致。

## 八、报价管理（quotes）

1. 点「+ 新建报价」，选客户、填标题与有效期，添加明细行（选产品自动带标准价，可改成交单价与数量）；
2. 弹层底部实时计算「标准额 / 报价额 / 折扣」，超过审批线（默认 15%）会提示「超审批线，保存后需总监批准」；
3. 保存后状态自动判定：超阈 →「待审批」，否则「草稿」；
4. 待审批单由销售总监或管理员打开后「批准 / 驳回」；驳回须填原因；
5. 草稿与已批准可「发送给客户」，已发送可标记「客户已接受」。

> 没批准就发送会被拦下：超阈折扣的报价必须先走审批，这是毛利保护的基本盘。

## 九、合同管理（contracts）

1. 点「+ 新建合同」，选客户、填标题、金额、签署日期、付款条件（3-4-3 / 5-5 / 一次性）、关联商机；
2. 保存即按付款条件生成回款计划（应收日 = 签约日 + 30 天 × 期序，末期兜底尾差），合同状态「待签署」；
3. 打开详情点「签署合同」：状态转「已签署」，计划按实际签署日重排；若关联商机在谈，商机自动推进为「赢单」；
4. 详情内「登记收款」登记回款；管理员/总监可「终止」（须填原因）；
5. 列表展示回款进度条与逾期金额，侧栏给出合同额、已收、回款率、待签署数。

## 十、回款管理（payments）

- 四张 KPI：未收合计、逾期未收、本期已收、收款笔数；
- 「应收账龄」五档：未到期 / 1-30 / 31-60 / 61-90 / 90 天以上；
- 「回款计划」列表可按「只看逾期」过滤，展示每期应收、已收、未收、状态、逾期天数；
- 「+ 登记收款」默认按到期日 FIFO 核销（也可在合同详情里指定期次）；全部收齐合同自动转「已完成」；
- 「收款流水」列出收款单号、合同、客户、金额、日期、方式、经办。

## 十一、服务工单（tickets）

1. 顶部四张 KPI：SLA 超时、待受理、处理中、平均满意度；
2. 「+ 新建工单」选客户、填标题、类别（故障/咨询/投诉/需求）、优先级（P1/P2/P3）、问题描述；
3. 提交后按优先级计算 SLA：P1 4 小时、P2 8 小时、P3 24 小时；响应时限为期的一半（最少 1 小时）；
4. 列表展示 SLA 状态（正常/临期/超时/已完成）与剩余小时数（负数表示已超）；
5. 详情操作：受理 → 解决（填处理结论）→ 关闭并评价（1-5 分）；随时可「回复」留言；
6. 侧栏说明 SLA 口径与优先级分布。

## 十二、市场活动（campaigns）

- 顶部「整体 ROI」等 KPI；列表展示活动编码/名称、类型渠道、起止、预算与投入、线索数与目标、ROI、CPL、预算执行率、线索达成率；
- 下方柱图对比各活动投入产出；「+ 新建活动」录入名称、类型、渠道、预算、投入、目标线索数。

## 十三、报表分析（reports）

六个标签：

| 标签 | 内容 |
|---|---|
| 销售漏斗 | 在谈金额、加权预测、赢单率、平均客单；阶段漏斗与相邻转化；阶段金额柱图；负责人维度漏斗（含赢率预警线） |
| 业绩排行 | 目标、签约额、达成率进度条、单数、客单价、在谈、加权、回款；签约额对比柱图 |
| 来源转化 | 各来源线索数、转客户数、转化率、赢单数、签约额、平均客单 |
| 销售预测 | 滚动 3 个月（可调）加权/乐观/悲观预测曲线与分月明细 |
| 应收账龄 | 未收合计、逾期、逾期占比；五档账龄分布；逾期 TOP 客户 |
| 服务分析 | 平均满意度、平均解决时长、工单总量；按优先级与类别分布 |

## 十四、集成中心（integration）

仅系统管理员可见（其他角色看到说明页，不影响业务接口权限）。

| 标签 | 用途 |
|---|---|
| API Key | 新建/吊销对接 Key（只读或读写），明文仅显示一次 |
| Webhook | 新建订阅（名称、回调地址、密钥、事件），可测试与删除；列出支持的事件清单与签名算法 |
| 投递日志 | 按状态过滤，查看 http 码与失败原因，手动重发 |
| 外部 ID 映射 | 绑定外部系统主键与本地单号，支持按对象类型与系统过滤 |
| 增量同步 | 展示变更游标与示例，可复制 curl 直接用 |

页面顶部给出三条通道（REST 拉取 / Webhook 推送 / 增量同步）的 curl 示例，以及 OpenAPI 契约入口。

## 十五、基础设置（settings）与操作日志（logs）

- 「业务规则」：8 条规则的阈值与启停（查重线、公海天数、折扣审批线、三档 SLA、赢率预警线、预测月数），管理员可直接改数字或勾选启停，改完立即生效并写日志；
- 「团队与用户」「销售目标」：展示团队、用户角色、期间目标；
- 「操作日志」：最近 200 条操作留痕（时间、操作员、动作、详情）。

## 十六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 新建线索提示「疑似重复」 | 手机号/邮箱命中，或公司名相似度超阈值 | 打开候选核对；确属新客户可强制保存 |
| 商机推进报「需补齐：决策人」 | 阶段闸口未满足 | 在详情或推进弹层补录决策人/竞品 |
| 报价发送被拦 | 折扣超审批线且未批准 | 由总监/管理员先批准 |
| 登记收款报「超过合同未收余额」 | 收款额大于剩余应收 | 核对金额或先补合同变更 |
| 工单显示「超时」 | 已过 SLA 解决时限 | 尽快处理并填结论；超时会进预警 |
| 页面空白/提示仅管理员可见 | 该页对当前角色不开放 | 换管理员账号或联系管理员开通 |
| DEMO 里刷新后数据回退 | 离线版写操作只在内存 | 属预期；正式系统会落库 |

## 十七、数据与运维

- 数据库：`data/feiying.db`（SQLite，WAL）；备份 = 停止服务后拷贝该文件（含 `-wal`/`-shm`）；
- 重置演示数据：删除 `data/feiying.db*` 后重启，自动重灌确定性数据（`SEED=20261020`，日历锚点 2026-10-20）；
- 健康检查：`GET /api/health` 返回服务状态与关键对象计数，可接监控；
- 日志：操作日志在系统内查看，Webhook 投递日志在集成中心查看；进程标准输出仅打印异常堆栈。
