# 飞鹰CRM系统建设方案

## 项目背景与建设目标

飞鹰CRM 面向「工业品 / 装备制造 / 项目型销售」的中型 B2B 团队，解决三条主线问题：线索来源多、跟进靠记忆，客户资料散在个人手里，商机赢率与回款进度说不清。系统把「线索 → 客户 → 商机 → 报价 → 合同 → 回款 → 服务」做成一条可度量的流水线，并用业务规则把管理动作固化进系统，而不是靠人盯人。

建设目标：

1. **一条主线跑通**：线索查重分级、客户 360、商机阶段闸口、报价折扣审批、合同回款计划与账龄、服务工单 SLA，全流程线上闭环。
2. **口径统一**：漏斗加权、赢率、客户健康分、SLA 时限、市场 ROI 等指标全部由后端纯函数内核计算，页面、报表、导出同一套口径。
3. **可对接**：完整 REST 契约 + Webhook 推送 + 增量同步三条通道，留足与 ERP、BI、客服系统、财务系统对接的接口。
4. **零依赖可跑**：后端只用 Python 标准库（http.server + sqlite3），前端只用原生 HTML/CSS/JS，单机一条命令启动，交付与运维成本极低。

> 定位说明｜飞鹰CRM 是「系统建设样板 + 可运行生产骨架」，不是 SaaS 多租户产品：默认单组织、单账套，多组织/多币种/多语言留作后续演进。

## 需求范围

| 域 | 功能 | 关键规则 |
|---|---|---|
| 营销获客 | 线索池、线索查重、分级、分配/领取/回收、市场活动与 ROI | 手机号/邮箱强重复拦截；名称相似度 + 前缀闸口；预算分档 A/B/C |
| 客户经营 | 客户档案、联系人、客户 360（六标签）、健康分 | 跟进新鲜度 30 + 回款 40 + 在谈 20 + 满意度 10 − 逾期扣分 |
| 销售过程 | 商机看板/列表、阶段状态机、阶段闸口、跟进记录 | 只能前进可跨级；赢单只能从「商务谈判」进入；结单锁定 |
| 交易与回款 | 报价（明细/折扣/审批/发送/接受）、合同（付款条件/签署/终止）、回款计划与核销、账龄 | 折扣超阈进审批；合同签署自动生成回款计划并按签署日重排 |
| 客户服务 | 服务工单、SLA 计时、受理/解决/关闭评价、回复 | P1 4h / P2 8h / P3 24h；响应时限 = 一半（最少 1h） |
| 分析 | 漏斗与相邻转化、业绩排行、来源转化、销售预测、应收账龄、服务分析 | 加权 = 金额 × 赢率；预测给加权/乐观/悲观三档 |
| 系统 | 用户角色、业务规则启停与阈值、操作日志、集成中心 | 7 类角色权限点 + 销售数据范围隔离 |

不在一期范围：经销商门户、CPQ 复杂配置报价、多渠道客服工作台、BI 自助建模、移动端原生 App（页面已做窄屏适配）。

## 总体架构

### 技术选型与取舍

| 层 | 选型 | 取舍理由 |
|---|---|---|
| 后端 | Python 3.10+ 标准库 `http.server` + `sqlite3` | 零第三方依赖，交付即跑；SQLite WAL + 全局写锁足够支撑中型团队（实测 200 并发读、50 并发写无错） |
| 数据 | SQLite（29 表 / 8 索引），单文件 | 备份 = 拷文件；后续换 MySQL/PG 只需改 `db.py` 的 DDL 与连接 |
| 前端 | 原生 HTML/CSS/JS（hash 路由 + `F` 命名空间） | 无构建链、无 node_modules，改一行刷新即见 |
| 集成 | REST + Webhook(HMAC-SHA256) + 增量游标 | 覆盖「拉、推、对账」三种典型对接方式 |
| 测试 | pytest + Playwright（Edge/Chromium headless） | 三层门禁：纯函数单元、接口全流程、端到端 UI |

### 分层与目录

```
feiying-crm/
├─ backend/
│  ├─ crm.py        业务内核（纯函数：状态机 / 查重 / 评分 / 漏斗 / 回款计划 / SLA / 签名）
│  ├─ db.py         建表与连接（29 表 DDL、WAL、busy_timeout）
│  ├─ seed.py       确定性演示数据（SEED=20261020，日历锚点 2026-10-20）
│  └─ server.py     REST 服务（80 条路由、鉴权、幂等、限流、Webhook 投递线程）
├─ frontend/        14 个页面（app.js 框架 + sales/deal/svc/intg 四组业务页）
├─ tests/           单元 53 项 / 接口 59 项 / 端到端 14 项
├─ tools/           DEMO 构建、文档构建、知识库上传、GitHub 推送
├─ deploy/          部署包构建
└─ demo/            离线单文件演示（无需服务与网络）
```

分层原则：**能算的规则全部下沉到 `crm.py`（无 IO、无 SQL、可单测对拍），服务层只做取数、落库、视图组装**。这样「赢单必须从商务谈判进」这种规则在接口、页面、测试里只有一份实现。

### 运行时与并发

- 所有 `/api/` 请求在一把 `RLock` 内串行执行（SQLite 单写者模型），读请求同样走锁，避免长事务与脏读。
- Webhook 投递由后台线程承担：每 5 秒扫描「待投递」，失败按 30/60/120 秒退避重试 3 次。
- 端口：默认 `8018`，可用 `FEIYING_PORT` 覆盖；数据库路径 `FEIYING_DB` 覆盖（默认 `data/feiying.db`）。

## 数据模型

29 张表分六组：

| 分组 | 表 | 说明 |
|---|---|---|
| 组织与权限 | `users` `sessions` `teams` `targets` | 账号、会话、团队、销售目标 |
| 客户与线索 | `customers` `contacts` `leads` `pool_logs` | 客户/联系人、线索、公海流水 |
| 销售过程 | `opportunities` `stage_logs` `activities` `products` | 商机、阶段轨迹、跟进记录、产品价目 |
| 交易与回款 | `quotes` `quote_lines` `contracts` `contract_plans` `payments` | 报价头行、合同、回款计划、收款单 |
| 服务与营销 | `tickets` `ticket_logs` `campaigns` `campaign_members` | 工单与轨迹、市场活动与成员 |
| 规则与集成 | `rules` `op_logs` `api_keys` `webhooks` `webhook_deliveries` `ext_mappings` `change_log` `idem_keys` | 业务规则、操作日志、Key、订阅与投递、外部 ID 映射、变更流、幂等缓存 |

关键约束：业务单号唯一（`leads.no`、`opportunities.no`、`quotes.no`、`contracts.no`、`payments.no`、`tickets.no`），单号规则为 `前缀 + yyyyMMdd + -序号`（`LD/QT/CT/SK/OPP` 4 位、`TK` 6 位），按当日 `MAX(no)` 递增，串行化写保证不重号。

索引 8 个：线索状态、商机阶段、跟进对象、回款计划合同、工单状态、变更游标、投递状态、外部映射。

## 核心流程设计

### 线索到客户（MQL → 客户）

1. 线索入库：手机号与邮箱至少填一个；建单即跑查重（手机号归一后相同 → 强重复；邮箱相同；公司名相似度 ≥ 阈值且共有前缀 ≥2 字或一方包含另一方 → 疑似）。命中返回 409 与候选清单，前端提示「确认要新建请加 force=true」。
2. 分级：预算 ≥50 万 A、≥15 万 B、其余 C；来源为「展会 / 老客推荐」上浮一档。
3. 归属：待分配 → 分配/领取 → 跟进中；超过 `pool_days`（默认 30 天）未跟进自动回收公海，任何销售可领取。
4. 转客户：生成客户编码 `C-0001` 序列，同步建主联系人，写公海流水与变更事件。

### 商机阶段状态机

`初步接触(10%) → 需求确认(25%) → 方案报价(50%) → 商务谈判(75%) → 赢单(100%) / 输单(0%)`

- 只能前进、可跨级，不能回退；
- 赢单只能从「商务谈判」进入，且必须已签署合同；
- 阶段闸口：进入「需求确认」须有决策人；「方案报价」须有金额；「商务谈判」须决策人 + 竞品；「赢单」须已签署合同。
- 推进时可顺带补录闸口字段（竞品 / 决策人），补完即校验、即落库；
- 结单（赢单/输单）后锁定，需「重开」另建商机——保证历史赢率不被事后修改。

### 报价折扣审批

折扣率 = 1 − 报价额 / 标准额（标准额取产品价目 × 数量）。折扣率超过规则阈值（默认 15%）自动进入「待审批」，销售总监批准后才能「发送」，客户接受后转「已接受」；驳回须填原因。低于阈值可直接发送。

### 合同与回款

- 新建合同按付款条件（`3-4-3` / `5-5` / `10` 等）等间隔生成回款计划：应收日 = 签约日 + 30 天 × 期序，末期兜底尾差，总额精确等于合同额。
- 签署：状态转「已签署」，回款计划按实际签署日重排；若关联商机且商机在谈，自动推进为「赢单」。
- 收款：默认按到期日 FIFO 核销，也可指定期次；未收清零的期次转「已收」，全部收齐合同转「已完成」。
- 账龄分档：未到期 / 1-30 / 31-60 / 61-90 / 90 天以上，口径用于报表与逾期预警。

### 服务工单与 SLA

P1（系统不可用）4 小时、P2（功能异常）8 小时、P3（咨询/需求）24 小时；响应时限 = SLA 的一半（最少 1 小时）。剩余 ≤2 小时标「临期」，超期为「超时」，解决/关闭后为「已完成」。工单流转：待受理 → 处理中 → 已解决 → 已关闭（关闭时录满意度 1-5）。

### 市场活动与 ROI

以活动编码归因线索与签约：ROI =(归因签约额 − 投入)/ 投入，CPL = 投入 / 线索数，预算执行率 = 投入 / 预算，线索达成率 = 线索数 / 目标线索数。

## 业务规则引擎

规则集中在 `rules` 表，可在「基础设置」启停与改阈值，改完立即生效并写操作日志（在途单据不受影响）：

| 规则编码 | 默认值 | 作用 |
|---|---|---|
| `dup_check` | 0.62 | 线索查重名称相似度阈值 |
| `pool_days` | 30 天 | 未跟进自动回收公海天数 |
| `discount_approval` | 0.15 | 报价折扣审批线 |
| `sla_p1` / `sla_p2` / `sla_p3` | 4 / 8 / 24 小时 | 工单 SLA 解决时限 |
| `win_rate_alert` | 0.35 | 赢率预警线（报表标注） |
| `forecast_months` | 3 个月 | 预测默认滚动月数 |

## 权限与数据范围

7 类角色对应权限点：`admin`（全权）、`sales_director`（读写 + 折扣审批 + 财务）、`sales`（读写）、`sdr`（线索读写）、`service`（服务）、`finance`（财务）、`marketing`（市场）。数据范围：销售角色只能看自己名下的客户 / 商机 / 合同 / 回款计划；总监与管理员可见全域。集成配置（API Key / Webhook）仅 `admin`。

## 集成方案

对外提供三条通道，覆盖「拉、推、对账」：

1. **REST 拉取**：`Authorization: Bearer fyk_...`（API Key，`key_hash` 存 SHA-256，支持 read/write 范围与有效期），分页 `page/pageSize`。
2. **Webhook 推送**：订阅事件（`lead.created`、`opportunity.stage_changed`、`opportunity.won`、`quote.approved`、`contract.signed`、`payment.received`、`ticket.created` 等），头部带 `X-FYC-Event / X-FYC-Timestamp / X-FYC-Signature / X-FYC-Delivery`，签名 `sha256=HMAC_SHA256(secret, timestamp + "." + body)`；失败退避重试 3 次，投递日志可查可手动重发。
3. **增量同步**：`GET /api/sync/changes?since=<游标>&object=<对象>`，`change_log` 自增游标只增不减，可断点续传，适合定时对账。

配套能力：`Idempotency-Key` 幂等（重复提交回放首次响应并带 `X-Idempotent-Replay: true`）、限流 240 次/分钟/Key（429 + `Retry-After`）、外部 ID 映射与反查（`/api/integration/resolve`）、机器可读契约 `/api/openapi.json`（OpenAPI 3.0）。

## 前端设计

14 个页面：销售驾驶舱、线索池、市场活动、客户档案、商机看板、跟进记录、报价管理、合同管理、回款管理、服务工单、报表分析（6 标签）、集成中心（5 标签）、基础设置、操作日志。

交互约定：三栏骨架（导航树 / 工作区 / 侧栏摘要）+ 底部状态栏；列表页统一「关键字 + 状态下拉 + chips 计数」；详情统一弹层，弹层底部按状态给出可执行动作；业务提示走状态栏 toast 且 6 秒内不被页面摘要覆盖。

## 报表与指标口径

| 指标 | 口径 |
|---|---|
| 在谈金额 / 加权 | 进行中商机金额之和 / Σ(金额 × 阶段赢率) |
| 赢单率 | 赢单数 ÷ (赢单数 + 输单数) |
| 平均客单 | 赢单金额 ÷ 赢单数 |
| 相邻转化 | 下一阶段金额 ÷ 上一阶段金额 |
| 销售预测 | 按预计结单月聚合；乐观 = 全额 ×0.85，悲观 = 加权 ×0.7 |
| 客户健康分 | 跟进新鲜度 30 + 累计回款 40（对数、30 万封顶）+ 在谈 20（3 个封顶）+ 满意度 10 − 逾期每笔 8（最多 −24） |
| 应收账龄 | 按回款计划应收日与今天之差分五档 |
| SLA | 响应时限 = 解决时限 ÷ 2（最少 1h）；剩余 ≤2h 临期，<0 超时 |
| 市场 ROI | (归因签约 − 投入) ÷ 投入 |

## 非功能设计

- **性能**：首页 `bootstrap` 单请求聚合 KPI/漏斗/待办；列表默认 100 条/页、上限 500；报表走全量聚合（万级数据 <200ms）。
- **安全**：会话 Token（登出即失效）、API Key 哈希存储、密码加盐哈希、写操作权限点校验、webhook 签名防伪造、幂等键防空重。
- **可用性**：SQLite WAL + `busy_timeout`；异常统一返回中文原因；前端 401 自动回登录页。
- **可运维**：操作日志留痕、投递日志可重发、规则可在线调整、数据单文件可备份。

## 风险与演进

| 风险 | 影响 | 应对 |
|---|---|---|
| 单写锁在超大并发下排队 | 峰值写入延迟 | 预留读写分离/换 PG 的迁移脚本；接口层已抽象取数函数 |
| 线索查重误报/漏报 | 重复客户或拦截新建 | 阈值可调 + 返回候选清单人工确认 + `force=true` 放行 |
| 折扣审批线下串通 | 毛利受损 | 审批留痕、报表按折扣区间分析、后续接 ERP 价格校验 |
| 回款核销口径争议 | 账龄失真 | FIFO 与指定期次双模式，收款单可追溯到期次 |

后续演进：多组织多币种、商机团队协作（联合跟进与分成）、移动端与企业微信集成、CPQ 配置报价、客户成功（续约与健康度预警）。
