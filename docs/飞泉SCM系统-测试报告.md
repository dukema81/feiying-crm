## 2. 测试策略与环境

### 2.1 分层策略

- **单元层**：`backend/scm.py` 业务内核全部纯函数，无 IO 无 SQL，直接断言口径（评级、状态机、三单匹配、库存、ABC、账期、签名）。任何口径修改先改这里，全链路口径的唯一真相源。
- **接口层**：pytest 夹具为每个 session 起独立临时库 + 独立服务进程（端口 8941），跑通「登录 → 建档 → 请购 → 询价 → 订单 → 收货 → 质检 → 入库 → 发票 → 匹配 → 付款 → 结算 → 调拨 → 盘点 → 报表 → 集成」全链路，并覆盖权限闸口与异常分支。
- **端到端层**：Playwright（Edge/Chromium headless）驱动真实浏览器，14 个页面逐页渲染断言 + 关键交互（供应商 360、请购创建、批次视图、三单对照、Key 生命周期、权限锁定），全程收集控制台错误。

### 2.2 环境

- Python 3.13 / SQLite（WAL）/ Windows 与 Linux 均验证。
- 测试库与开发库完全隔离（`FEIQUAN_DB` 指向临时目录，进程结束即弃）。

## 4. 关键验证点（抽样）

### 4.1 状态机与闸口

- 已下单订单推进回「草稿」→ 400「采购订单只能向前推进」。
- 终态订单（已结算 / 已取消）任何推进 → 400。
- 全部到货闸口：收货量 90 < 订购量 100 → 缺失项「到货数量未达订单数量」。
- 已结算闸口：无发票或匹配未通过 → 缺失清单列出 2 项。

### 4.2 三单匹配

- 收货 9800 / 发票 9900 → 通过（差异率 1.02%）。
- 发票 10500（差异率 7.14%）→ 金额差异超限；此时付款 → 400「三单匹配未通过，不能付款」。
- 容差自定义 6% 时 10500 通过、4% 时拒绝，验证规则可调。

### 4.3 权限与集成

- buyer（zhouhao）批准请购 → 403；仓管（sunlei）新建请购 → 403；财务（huangli）可推进「已结算」。
- read Key 调用 `POST /api/requisitions` → 403；`X-Fq-Key` / `Authorization: Bearer` 两通道均可鉴权。
- Webhook 测试事件入队后可在投递记录查到；失败记录可手动重投。
- 增量同步：since=0 拉取 10 条返回 cursor，续拉首条 id > cursor；object=po 过滤生效。

## 5. 缺陷台账

本轮开发与测试共记录 9 项缺陷，全部修复并回归验证：

| # | 现象 | 根因 | 修复 | 验证 |
|---|---|---|---|---|
| D-01 | 种子数据到货准时率恒为 1.0 | 演示数据全部按时到货 | 收货日期引入随机延迟（25% 概率延迟 1-5 天） | 报表准时率呈真实波动（7/9≈0.78） |
| D-02 | 物料 ABC 全为 C | 判定用「加入后累计占比」，最大项恰好 100% 判 C | abc_classify 改用「加入前累计占比」，最大项必为 A；种子按年耗用金额分类 | 单元测试 + 重算后 A/B/C 三档分布 |
| D-03 | 财务推进「已结算」返回 403 | api_order_stage 统一 require(write)，财务无 write | 「已结算」单独放行 finance 权限 | 接口测试 test_finance_can_settle_order |
| D-04 | CSV 导出 JSON 解析失败 | CSV 带 BOM | 冒烟脚本只校验状态码与行数 | 通过 |
| D-05 | 文档记载的 `X-Fq-Key` 头不生效 | 服务端 _tokens 未读取该头 | 取票头列表加入 X-Fq-Key（置于首位） | 接口测试 test_key_auth_works |
| D-06 | 「待匹配」发票显示匹配结果「通过」 | 种子给待匹配状态也写了匹配结果 | 种子待匹配发票 match_result 置空 | 新种子库目检 + 快照 |
| D-07 | 询价定标测试找不到「询价中」单据 | 种子只有已定标询价 | 种子补一张询价中比价单（3 家报价） | 接口测试无 skip |
| D-08 | 供应商准入前未校验资质但测试未覆盖 | 准入闸口存在但无负面用例 | 测试先准入后补资质失败路径 | test_create_and_admit 覆盖 |
| D-09 | 库存台账侧栏「库容分布」在汇总视图显示占位行 | 汇总视图无仓库字段 | 汇总视图改为 ABC 结构展示，批次视图才显示库容分布 | UI 巡检截图 |

## 6. 性能观测

- 冷启动（建库 + 种子 14 供应商 / 24 物料 / 26 请购 / 17 订单 / 130+ 流水）约 1.2 秒。
- `/api/bootstrap`、`/api/reports` 等重查询在演示数据量下均 < 60ms。
- 端到端 14 页全遍历（含截图）52 秒，平均每页 < 1.5 秒（含 Playwright 开销）。
- SQLite WAL + 全局锁串行化在演示并发规模下无争用；`busy_timeout=20000` 兜底。

## 7. 遗留风险与建议

- Webhook 投递为进程内后台线程，重启期间事件不补发；重要对接建议以增量同步为主、Webhook 为辅。
- SQLite 单文件适合单机 / 小团队规模；多实例水平扩展需迁移 PostgreSQL（数据模型可直接平移）。
- 演示种子数据随机种子固定，重建即复原；生产使用请清空种子只保留基础规则与账号。
